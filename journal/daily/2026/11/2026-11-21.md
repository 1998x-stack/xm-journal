# 今天发生了什么

## 早晨：七点半出发，开始一天的课程

今天早上起得比较早，七点半就出发了。早餐吃了汉堡。我想，如果再提前一点，或许就能吃上鸡蛋。这个小细节提醒我，早晨的安排不仅取决于起床时间，也取决于前一天有没有把节奏准备好。

上午上了两节课。整体感觉不错，讲解比较深入。第一部分集中在数形结合的填空压轴题：这类题目对不少学生来说是一个难点，关键不是多做几道题，而是把图形、数量关系和解题路径真正联系起来。

另一位同学的立体几何也值得继续往深处讲。我把重点放在第一道证明题上，希望把证明的思路讲透，让学生面对不同题目时，能够更快识别条件、组织推理，而不是只记住某一道题的答案。

今天又强化了一个教学判断：**宁可把几道题、几个类型讲透、做透，也不要为了覆盖面而广泛堆题。**

## 课堂不应该只发生一次：把讲解沉淀成教学资产

上课时我想到，应该打开手机录音，把课堂过程记录下来。以后每节课都可以在合适的前提下录音，再整理成文字、知识点和典型题型。这样一次课堂就不只是当时讲过、下课后容易散掉的内容，而有机会成为可以回看、修改和复用的教学材料。

这件事今天还只是一个明确的想法，并没有把录音和整理流程真正建立起来。开始实施前，也需要确认课堂参与者知情，以及录音内容的保存和使用边界。

## 午后：手工导入太慢，应该让脚本接管重复劳动

两节课之后，我去按摩、休息了一会儿，中午吃饭。回来后，我把一些数学题目逐个导入 ChatGPT，让它们分别生成相应内容。

这个过程让我很清楚地感受到：逐题手工输入的速度太慢了。与其每次重复同样的操作，不如认真设计一套脚本，把题目导入、转换和生成流程串起来，后面可以批量运行。

之后还有一节课，我也意识到这类课堂同样值得记录。随后我去了复旦，并安排了游泳。

## 游泳：舒服、自由，也需要提前准备

游泳的体验很好，感觉开心、舒服、自由。我越来越觉得，生活里有些事情并不复杂，真正影响能不能顺利开始的，是有没有提前准备好。

如果晚上就把泳衣、泳裤等装备放好，第二天出门时就不必临时寻找和收拾。把准备工作前置，能让自己更容易把游泳变成稳定的安排。

## 晚上：把过去学过的东西重新变成资产

回家后，我继续想到自己积累的 GitHub 仓库。仓库不少，但教程类内容还需要逐步分类和整理。下一步，我希望把它们一个个梳理出来，使用相应的 Skill 转换成结构清晰、可持续维护的教程。

过去大学里学过的微积分、线性代数等课程，也可以逐步整理成自己的教程仓库。学过的东西如果没有留下结构、例子和解释，时间久了就容易忘掉；如果能把它重新整理、验证并保存下来，过去投入的学习时间才更容易转化为长期可用的资产。

我希望这件事不是停留在想法上，而是从一个仓库、一个课程开始，分批推进，并逐渐形成可重复的转换流程。

## 游戏里的提醒：先活下来，再决定进退

玩《和平精英》时，我想到一个看起来很简单、但真正做到并不容易的原则：**首先要保证自己活着。打得过就打，打不过就跑。**

这句话背后其实是先判断最重要的东西是什么。不能因为眼前出现一个目标，就忘了自己最需要保护的核心。一旦失去生存这个前提，后面的选择空间也会消失。

我意识到，理解一句战术原则并不难，难的是把它变成每次行动前都会自动出现的判断。它需要在具体情境里反复练习：先看局势，再判断胜算，最后决定进攻还是撤退。

# 今天真正意识到的事情

今天的经历看起来分散：讲数学、整理题目、游泳、梳理 GitHub 仓库、玩游戏。但我反复想到的是同一件事：**先弄清楚什么最值得保住，再把有限的时间和精力投入到真正重要的地方。**

我把它整理成四个连续动作：

1. **守住核心**：先确认最重要的目标和底线，不为了眼前的局部收益丢掉全局。
2. **做深关键部分**：教学不追求题目数量，而是把关键题型和推理过程讲透。
3. **留下可复用的东西**：课堂录音、题目整理、课程笔记和教程仓库，都可以让一次投入留下痕迹。
4. **减少重复劳动**：把重复的导入、转换和整理步骤写成脚本，让时间更多花在讲解、理解和判断上。

这里的“守住—做深—沉淀—复用”是我对今天几段经历的归纳，不是说这些流程已经全部完成。课堂录音、批量脚本和旧课程整理，都还需要真正开始并持续迭代。

# 给自己的提醒

**不要只追求今天做了多少事情。先保住真正重要的东西，把关键问题做深，再把过程沉淀下来，让一次投入能够在以后继续产生价值。**
