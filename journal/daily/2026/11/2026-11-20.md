# 今日概览

围绕 xm-journal 的第二阶段，开始从静态文档骨架转向可运行的数据管线。设计原则是把 GitHub 可验证事件与人工记录分开：GitHub 用于证明提交、PR、CI 和部署状态；对话背景、决策原因、学习与价值判断仍由人工日报补充。

## 关键决策

- GitHub 事件数不代表工作价值；PR 只有 merged_at 才算合并，部署只有 deployment status=success 才算成功。
- API 权限错误和缺失快照不能解释成零活动；报告应明确展示覆盖率与采集异常。
- 周报使用 ISO Monday–Sunday，月报使用自然月；周期完整性与人工日志覆盖率分开统计。
- 不尝试自动读取 ChatGPT 全部对话；由人工 Markdown 记录补足上下文、反思和下一步。

## 阻塞与风险

- 当前正在验证 GitHub Actions 上的端到端测试、跨仓库 API 权限、报告构建和 Pages 部署。
- 需要确认所有六个公开仓库的 Actions / deployments API 均可访问；若单个来源不可访问，报告必须显示不完整。
- 还需要进行真实手机端浏览器检查与历史日期回填测试。
